Draw outlines, edit pixels, ship OpenType.

FontCarver is a desktop font editor with a Rust kernel. Outlines and bitmap strikes live in the same document, a 65,535-glyph CJK family gets the same tools as a single-master Latin face, and the tables you never touched come back out of the exporter unchanged.

Get FontCarver Source on GitHub

Early development. Phases P0 to P4 are complete within the scope each acceptance report states; P5 is in progress and there is no packaged release yet. Read the status record

§1
Capabilities

Four things the editor refuses to treat as an afterthought.

Most editors are built around one kind of font and grow the rest later. The document model here starts with all four.

Curves and pixels, one document

Cubic and quadratic outline editing and bitmap-strike editing are the same document, not two applications. Trace pixels into outlines, rasterise outlines into a strike, then fix the strike by hand.

Latin and CJK, same tools

The glyph grid, search, batch operations and file input and output are built for 65,535-glyph fonts. Components, vertical metrics and vertical layout features are part of the model rather than a plug-in.

OpenType layout you can read

GSUB, GPOS, GDEF, BASE, MATH, STAT, COLR and CPAL, edited as feature-file source or through the interface, compiled with fea-rs and fontc, with diagnostics located in your own source.

Lossless where you did not touch anything

Tables the model does not represent are preserved verbatim through open and export, and glyphs you did not edit keep their hinting. Opening a font is not a lossy act.

§3
Guide

A first session, start to finish.

Four steps from an existing font to one you exported yourself. Keys are shown for Windows and Linux; on macOS, Ctrl is ⌘.

Open a font

Open a TTF, OTF, UFO, Glyphs or SFD file, or a FontCarver document. What the model cannot represent is kept verbatim rather than dropped, so you can open a font just to look at it.

  • CtrlO open
  • CtrlShiftP command palette

Edit outlines

Draw with the pen, cut with the knife, nudge nodes with the arrow keys. Smooth nodes keep their handles collinear, corner nodes do not, and every edit goes through one undo stack.

  • V select
  • P pen
  • B pencil
  • E knife
  • CtrlZ undo

Kern, then add features

Set kerning in the gap between two glyphs in a text tab, with shared groups and per-master pairs. Write the rest as feature-file source and read the compiler's diagnostics against your own lines.

  • CtrlI font info
  • T text tool

Export

Write a TTF or OTF back out. Glyphs you never edited keep their hinting, and the preserved tables are merged back in. Outline edits currently drop that glyph's hinting; the status record says where that stands.

  • CtrlS save
  • CtrlE export
$ fontcarver inspect DejaVuSans.ttf        # metadata and preserved tables
$ fontcarver check Source.fcf              # find problems, exit 1 on errors
$ fontcarver convert Source.glyphs Source.ufo
$ fontcarver build Source.fcf Source.otf --autohint
$ fontcarver shape Source.fcf "Hamburgefonstiv" --features liga,-kern

Build from source

You need Rust at the version pinned in rust-toolchain.toml, Node 24 or later, pnpm, and the Tauri system libraries. On Debian and Ubuntu those are libwebkit2gtk-4.1-dev, libgtk-3-dev, libayatana-appindicator3-dev and librsvg2-dev. 

$ git clone https://github.com/fontcarver/fontcarver.git
$ cd fontcarver
$ pnpm install
$ pnpm tauri dev                          # run the editor
$ cargo test --workspace                  # the Rust kernel's tests

§5
Status

Where the work actually stands.

A phase is complete within the boundaries its acceptance report states, not exhaustively. Native desktop input automation and release packaging are unverified for every phase so far.

  1. P0Shell, lossless round trip, glyph grid
  2. P1Outline editing, tools, export
  3. P2Kerning, editable OpenType layout, sources
  4. P3Bitmap strikes and bitmap formats
  5. P4Variable fonts, CJK construction, vertical
  6. P5Professional finish, hinting, packaging

One known defect is open: a Tibetan layout expansion-budget test fails, and the workspace test suite is not claimed green until it is diagnosed. That, and everything else, is tracked in the status record.

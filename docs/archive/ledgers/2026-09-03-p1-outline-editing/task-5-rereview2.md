### New Breakage in the Fix Diff

1. **Minor — a `Wait`er can return a stale run with no rebuild scheduled.** `crates/fw-layout/src/shaping.rs:285-289`: `await_publish` returns whatever font landed, and the arm computes `stale = compiled.generation != generation` without scheduling anything. Reachable when two first-ever shapes race at different generations (claimant at 3, waiter at 5, or the reverse): the waiter reports `stale: true` and nothing is pending, where the pre-fix code compiled its own font and returned fresh. Self-heals on the next shape (`plan` then returns `Rebuild`, `:237-240`).
2. **Minor — a `Wait`er woken by a *failed* first compile loses the diagnosis.** The synchronous `First` path propagates the compile error with `?` (`crates/fw-layout/src/shaping.rs:302`) and records no `BuildFailure`, unlike the worker (`:682-696`); the waiter therefore wakes on the claim release (`:149-161`), sees `claimed.is_none()` at `:713` and returns `Error::AbandonedCompile` → `ApiError::internal` (`crates/fw-api/src/error.rs:123-125`), not the `compile-failed: …` warning and not the underlying message. It does **not** spin — one predicate check, one return — and the claimant itself still gets the real error.
3. **Minor (test only) — the worker census can be read one instruction too early.** `crates/fw-layout/src/shaping.rs:982` exits the drain loop on `state.worker.is_none()`, but the exiting worker clears that flag at `:654-656` and only afterwards runs `WorkerGuard::drop` (`:580`) and `WorkerCensus::drop` (`:606-610`), so `assert_eq!(entry.live_workers…, 0)` at `:991` can observe a 1. Symmetrically `peak_workers` counts threads inside `run_worker`, not flag owners, so a successor spawned in the handoff window would record 2 without breaking the invariant. Both windows are sub-microsecond and the stress phase almost never produces a handoff (pending is refilled every ~50 µs against a 1 ms debounce); 10/10 runs passed.

No deadlock or lost-wakeup found. The checks behind that, one per scope item:
- (a) Every build-ending path notifies or is covered by the poll: worker publish `:698-701`; worker cancellation returns `:644`, `:665`, `:673` (already notified by `Entry::cancel`, `:465-468`); `First` publish `:308`; `First`/`MissingFont` early returns and unwinds via `Drop for ShapePlan` `:156-159`; `forget` `:361-369` and `Drop for Shaper` `:188-196` through `cancel`. The two silent paths — a worker build failure (`:682-696`) and `schedule`'s claim release (`:387`) — cannot strand a waiter, because a waiter exists only while `compiled` is `None` and a worker only exists after `schedule`, which requires `compiled` to be `Some`; and `await_publish` re-checks every `WAIT_POLL` = 50 ms anyway (`:721`), bounded by `FIRST_COMPILE_DEADLINE` = 300 s (`:707`, `:716-718`). The predicate is deliberately generation-agnostic (`:710`), which is what makes breakage 1 above possible but never a hang.
- (b) The session lock is released before any wait: `prepare` returns the plan out of `with_doc` (`crates/fw-api/src/handlers/shaping.rs:37-52`) and `shape_planned` is called at `:21-22`, outside it. This matters more than it looks — `Session::with_doc` takes a *global* documents `RwLock`, not a per-document one (`crates/fw-doc/src/session.rs:195-206`).
- (c) Lock order is always `entries` → `state`, never the reverse: `entry` (`shaping.rs:372-379`), `is_current` (`:348-354`) and `forget` (`:361-369`) are the only places that hold `entries`; `schedule` holds `state` across `thread::Builder::spawn` (`:382-395`) but takes no other lock, and `await_publish` releases `state` while blocked (`:719-722`). `Entry::cancel` notifies without the mutex, so `forget` does not invert anything.
- (d) Dropping a plan whose build is running is a no-op: `plan.claimed` is set false immediately after `schedule` (`:295`) and after the `First` publish (`:307`), and workers key off `pending`/`building`/`worker` (`:540-547`), never off the claim.
- (e) The token counter is per entry (`EntryState.next_token`, `:483`), monotone with `wrapping_add` (`:494-498`), and both comparison sites test `state.worker == Some(self.token)` / `Some(token)` (`:583`, `:654`) against the value `schedule` installed (`:391`).
- (f)–(i) as recorded in the verdicts above.

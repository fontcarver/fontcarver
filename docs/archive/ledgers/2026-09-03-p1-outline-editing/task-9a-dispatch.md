## Rulings (binding)
1. **New Font** (`Mod+N`, 480 px): family, style name, units per em (1000 / 2048 / custom), metrics preset (Latin default; CJK: 1000 upem, ascender 880, descender −120), starter glyph set (none / Basic Latin / Latin-1 / GB 2312). Flow: `session.new { family, units_per_em }` → one `doc.apply(Batch[SetFontInfo(style…), SetMasterMetrics(preset)])` → `glyphs.add` with the starter recipe (`A-Z a-z 0-9 …` for Basic Latin, `U+0020-U+00FF` for Latin-1, `@charset:GB2312`). Open the new document in a Font tab.
2. **Add Glyphs** (`Mod+⇧+G`, 560 px): recipe text area with syntax help, charset picker (list with counts and "already present" badges), virtualised preview list of the names that will be added, "Add N glyphs". Add an ADDITIVE `dry_run: bool` (serde default false) to `AddGlyphsParams` in fw-api so the preview and the counts come from the kernel's own recipe grammar (the result lists `added` names without applying anything; `skipped` explains duplicates/unknown/too-large). Keep the Rust change minimal, tested, `cargo fmt/clippy/test -p fw-api` green, `gen_ts` regenerated.
3. **Export** (`Mod+E`, 560 px): format tabs TTF / WOFF / WOFF2 / UFO / FWF (Designspace tab only when the document has more than one master); destination path with "Choose…" through the same native-dialog/path-prompt abstraction P0 uses for Save; options as checkboxes with a one-line explanation each (remove overlap, keep TrueType instructions, preserve untouched tables, production names — map to `ExportOptions` fields; leave out any that `ExportOptions` does not have and say so); master picker; "Export" runs `session.export`, disables the button, and shows the busy progress line under the tab bar driven by `ProgressEvent` (`compile`/`preserve`/`write` percents; `failed` terminates with an error toast carrying `message`); result view lists `ExportReport` warnings (`hinting-dropped` etc., mapped through the existing warning i18n) with the affected glyph names as chips (clicking a chip selects that glyph in the Font view if the tab is open — otherwise no-op) and "Reveal in folder" only if the platform abstraction can do it (otherwise omit and note it).
4. **Preferences** (640 px, left categories General / Editor / Snapping): theme (system/light/dark), language (en / zh-CN, switches i18next live), autosave interval, nudge steps (3 numbers), hit/snap distances, grid size, snapping toggles — wired to `prefs.get` / `prefs.set` with a small `prefsStore` (Zustand) that other views can read; applying is immediate; "Reset to defaults".
5. **Recovery**: on launch, call `session.recover_list`; if non-empty show the dialog (list with original path + timestamp; "Recover" → `session.recover` opens the document in a tab and shows a dismissible banner "Recovered from … — saving overwrites the original" driven by `DocSummary.recovered_from`; "Discard" → `session.discard_recovery` with a confirm step). Under the HTTP dev transport the same flow works (tests use it).
6. **Toasts and busy states** per §10 are shared infrastructure Task 11 is also touching (`ApiError.code` → i18n); do not modify `ToastStack`/`Toast` — call the existing toast API only. The progress line is a new small component under the tab bar (`app/src/shell/ProgressLine.tsx`) fed by a `progressStore` that subscribes to `Event.kind === "Progress"`.

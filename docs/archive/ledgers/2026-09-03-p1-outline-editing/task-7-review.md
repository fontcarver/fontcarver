### Issues

#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **Plan-mandated — a pencil stroke refits every contour in the layer.** `drawCommand` emits `PathOp::Simplify` (`tools/pencil.ts:178-190`), and `PathOp` is whole-layer by construction (`app/src/api/generated/Command.ts:326-338`, `PathOp.ts`); `fw_geom::simplify` loops over all contours and rewrites each one (`crates/fw-geom/src/edit.rs:76-99`). What the user experiences: drawing one freehand stroke into a glyph that already has outlines silently re-fits those outlines too — with `force_lines: true` near-straight curves become lines, with `smooth_curves: true` refitted endpoints are marked smooth, and every node may move up to 1 unit — all under a single undo entry labelled "Draw". `ignore_extrema: true` (`pencil.ts:52`) stops nodes being *added* but does not stop the refit. It is recoverable with one `Mod+Z`, but a user who does not notice ships altered outlines. Ruling 3 asked for a contour-scoped Simplify the kernel cannot express; the honest resolutions are a kernel `PathOp::Simplify` that takes contour indexes, or dropping the Simplify half and fitting in `fw-geom` via a new command. Either needs a controller decision.
2. **A rotate or scale previews a component as a slide, not as a turn.** `TransformGesture.preview` composes the full affine into `component.transform` (`gestures/transform.ts:167-183`), but the canvas turns that into a translation only: `componentDraws` reads `dx/dy` off `transform[4]/[5]` (`GlyphCanvas.tsx:502-503`) and `paintPath` applies just `ctx.translate(offset.dx, offset.dy)` (`drawComponents.ts:105`). So on a composite glyph — an accented letter, the common case — pressing `R` and dragging shows the base component sliding sideways while the layer's own contours turn, and the ghost jumps into place on the post-gesture reload. The committed geometry is right (`points.rs:157-159`), so this is a preview-only lie, but §13 makes the preview a contract. `ComponentDraw` needs the full affine delta rather than a `dx`/`dy` pair, or the path has to be re-parsed from the previewed component.

#### Minor (Nice to Have)
3. **`MeasureTool` never stops being busy.** `busy` is `from !== null && to !== null` (`tools/measure.ts:67-69`) and `pointerUp` deliberately keeps the measurement on screen (`:92-96`), so `ToolHost.claimsKey` falls back to `tool.busy` (`toolHost.ts:194-197`) and answers `true` for every key. Consequence: `path.toggleSmooth` is disabled (`views/glyph/glyphCommands.ts:209`) for as long as a measurement is displayed. Give `MeasureTool` a `claimsKey` that returns `false`.
4. **The snap halo can outlive the gesture.** `SnapRunner.forPoint` stores the match (`editorSnapping.ts:110`) and only `clear()` (called from drag start/finish, `editorController.ts:750`, `:766`) resets it, so after a pen click the halo stays drawn while the pointer moves on.
5. **Cut and extend drop contour identity.** `pathToContour` always writes `name: null, id: null` and `tt_index: 'Unnumbered'` (`pathGeometry.ts:91`, `:112`, `:126`), so a knife cut or a pen extend loses the source contour's UFO identifier, name and TrueType point numbering.
6. **An arrow press during a *live* drag is still ungated.** `nudgeSelection` passes `after: this.closing` (`editorController.ts:534`) but never calls `settle()`, and `this.closing` is undefined while a drag is merely open. The nudge's `edit_begin` then finalises the drag's edit and the drag's queued `edit_apply` is rejected. Not one of the four ruled probes, and pre-existing in shape, but it is the same class of defect carried item A closed.
7. **`editorController.ts` grew to 796 lines** (+298/−136), against ruling 1's "do not grow `editorController.ts`". Routing *was* extracted (`toolHost.ts` 248, `editorSnapping.ts` 116), so the intent was met; the file is one line under the hard cap with no headroom for the next task.
8. **Grid skipped below 4 px on screen** (`drawTools.ts:21`, `:38`) where §4.1 item 1 says "≥ 1 px spacing on screen". Defensible as readability, but it is a spec deviation the report does not list.
9. **`ShapeDialog` is not keyboard-trapped** (§9). No focus-trap helper exists anywhere in the app, so this matches every other dialog — worth one shared fix rather than one here. Separately, Enter while the Create button has focus runs `create()` from the div's `onKeyDown` (`ShapeDialog.tsx:63-65`) and the button's native click default action may follow; I did not observe a double commit (the dialog unmounts first) but a `create()` guard would make it impossible.
10. **`inferCurves` treats every `woff` as quadratic** (`pathGeometry.ts:390`), and WOFF/WOFF2 commonly wrap CFF. It only bites on a layer with no curves at all, so the blast radius is a first rectangle drawn in the wrong flavour.
11. **Dead or lint-appeasing code.** `transformsWholeLayer` is exported and unreferenced (`tools/transformTool.ts:251`); `ToolDefinition.live` is now read only by its own test (`tools/registry.test.ts:24`); `void get` in `prefsStore.ts:42` and `void context` in `pencil.ts:139` are no-ops.
12. **`ToolHost.consume` repaints on every routed event** (`toolHost.ts:236-248`), including every key-down that no tool claims, because `GlyphCanvas` offers each key to `controller.toolKey` (`GlyphCanvas.tsx:407-418`).
13. **A one-sided pen cubic puts the far control on the node** (`penPath.ts:86`), which is a valid but untidy degenerate cubic — the report's own concern 5.

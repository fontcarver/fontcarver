### Strengths

- The kernel change is genuinely minimal and honest: one flag, one early return before any mutation, the same grammar/duplicate/limit path, and tests that assert the *absence* of side effects (`glyph_count`, `dirty`, `undo_label`) rather than just the happy path.
- Every count in Add Glyphs comes from the kernel, so the dialog cannot drift from the recipe grammar — the one design decision that most reliably prevents a second parser in the UI.
- The progress store's terminal condition was written against the actual kernel contract, not guessed: `WRITE|FAILED at 100` matches `api.rs:38-40` precisely, so the line can never stick.
- Derived-not-stored preview state (`AddGlyphsDialog.tsx:63-66`) removes a whole class of stale-response bugs, and the debounce cleanup uses a `live` flag correctly.
- Tests exercise real parameter mapping through the mock transport (exact `toEqual` on `session.new`, the `Batch`, both `glyphs.add` variants and `session.export`), not just rendering; the e2e drives real menus and verifies the artefact with the CLI.
- `DEFAULT_PREFS`, `ExportOptions`, `MasterMetrics`, `DocSummary.recovered_from` and `ProgressEvent` all match the generated bindings and the Rust source exactly — I checked each.

### Issues

#### Critical (Must Fix)

None.

#### Important (Should Fix)

1. **A failed New Font leaves a half-initialised document and a second one on retry.** `newFont.ts:81-120` opens the tab in `createDocument` and only then runs `doc.font_info`, the batch and `glyphs.add`; any rejection propagates to `NewFontDialog.tsx:64-70`, which toasts and sets `busy = false` **without closing the created document and without closing the dialog**. A GB 2312 starter that hits an expansion limit, or a rejected batch, therefore leaves an untitled tab with the right family/upem but no style, no metrics and no glyphs — and pressing Create again mints a second document. Fix: `session.close` the document on failure (or keep the dialog closed and report on the created document). No test covers the failure path.
2. **The Dialog primitive does not have the chrome ruling 9 and §9 specify, and both the code comment and the report say it does.** `Dialog.tsx:36` claims "24 px padding, a 16/600 title"; the classes it uses give 12/16 px padding (`shell/dialog.module.css:21-35` with `--space-3: 12px`, `--space-4: 16px`) and a 15 px title (`--text-size-lg`, `tokens.css:23`). Body text is 13 px (`--text-size`), not the §9 14 px. The width classes were appended to the same file, so the padding/title overrides belong there too — this is a three-rule fix scoped to the new `.dialogSm/Md/Lg` selectors so the P0 path/close prompts are unaffected.
3. **A preference write before a successful `load()` persists the shipped defaults over the kernel's stored record.** `prefsStore.ts:93` builds the payload from `get().prefs`, which is `DEFAULT_PREFS` while `loaded` is false, and `persist` (`:61-79`) sends the whole record. If `prefs.get` fails (the store only toasts, `prefsStore.ts:81-91`), the very next theme click from the View menu (`builtinCommands.ts:56`) or any field in the dialog silently overwrites `recent_limit`, `autosave_seconds`, `nudge`, `grid_size` and `snap` with defaults. Guard `persist` on `loaded`, or re-read before the first write.

#### Minor (Nice to Have)

1. **Chips are unbounded.** `hinting_dropped_touched` (`crates/fw-compile/src/preserve.rs:381-391`) joins *every* touched glyph name into the message, and `ExportDialog.tsx:312-322` renders one button per parsed name with no cap — a font where a few thousand glyphs were edited produces a few thousand chip buttons in a modal whose sibling list is virtualised. Cap at ~50 with "+N more". (The parser itself is correct: I checked both `hinting-dropped` message forms against `preserve.rs:121-123` and `:385-389`; the "outline bytes are unavailable" variant has no `": "` tail and correctly yields no chips.)
2. **Three dead i18n keys** shipped to the translation pass: `dialog.addGlyphs.present`, `common.add`, `common.discard` — no `t()` call references them (grepped `app/src`).
3. **`skipped` is only ever a number.** `AddGlyphsDialog.tsx:212` shows "N skipped" and nothing else, so a typo'd name or a `too-large: …` token is indistinguishable from a duplicate. Ruling 2 asked the kernel to explain skips; the explanation never reaches the user.
4. **Charset rows mislabel every skip as "already present"** (`AddGlyphsDialog.tsx:92` sets `present: result.skipped.length`, rendered via `presentCount`). True for the four built-in repertoires, wrong in principle.
5. **Enter does not confirm Add Glyphs, Preferences or Recovery** — they pass no `onConfirm` to `Dialog`. Escape works in all five. Ruling 9 lists "Enter confirms" as a property of the primitive.
6. **The native-dialog "abstraction" is copy-pasted a third time.** `chooseExportPath`/`hasNativeFileDialog` (`exportFormats.ts:93-112`) repeat the `getTransport().kind === 'tauri'` + lazy-import shape of `sessionStore.ts:179-190, 231-248`; and where P0 falls back to `PathPromptDialog`, Export falls back to an inline hint. Extracting one `choosePath()` would make the constraint enforceable rather than conventional.
7. **A charset whose count fails is stuck on "counting…" forever** — the catch at `AddGlyphsDialog.tsx:95-98` does nothing, contradicting its own comment ("simply shows no counts").
8. **Number fields persist on every keystroke.** `PreferencesDialog.tsx:151, 185, 210` call `update` from `onChange`; clearing a field to retype makes `Number('')` → `0`, so an intermediate `grid_size: 0` / `nudge: 0` is written to the kernel before the real value. Commit on blur or debounce.
9. **`dismissedRecoveries` is append-only** (`uiStore.ts:333-338`) — never pruned when a document closes.
10. **Global shortcuts still fire under a modal.** `installShortcuts` binds on `window` in the capture phase and only skips editable targets (`shell/shortcuts.ts:183-196`), so `Mod+W` with the Export dialog open closes the document and the dialog silently unmounts (`DialogHost.tsx:26-30` returns `null` when the summary is gone). Pre-existing behaviour, but five new dialogs make it much more reachable.
11. `warningGlyphNames(warning)` is recomputed twice per warning during render (`ExportDialog.tsx:312, 314`).

### Assessment

**Task quality:** Needs fixes

**Reasoning:** Every ruling is implemented and the hard parts — the additive `dry_run`, the kernel-driven preview, the progress contract, the recovery-marker lifecycle — are correct against the kernel and the generated bindings, with tests that check the right things. Three things should be fixed before this is trusted: the New Font flow leaves a half-initialised document when a later call fails, a preference write before a successful load can overwrite the stored record with defaults, and the Dialog primitive claims §9 chrome numbers (24 px padding, 16 px title) it does not have.
